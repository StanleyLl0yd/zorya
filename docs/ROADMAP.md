# Zorya Roadmap

The roadmap tracks browser-product work. Web-engine milestones remain in the Rarog repository.

## Z0 — Bootstrap

Goal: establish a clean product repository and a reproducible Rarog dependency.

- Rust application skeleton;
- exact Rarog Git revision pin;
- Windows-primary, Linux-portability and Rust 1.85 CI;
- architecture, contribution, security and agent rules;
- no duplicated Web-engine implementation.

## Z1 — Native Shell

Goal: first useful developer browser host.

- platform-independent browser model with stable window and tab identities;
- one browser window with one active tab;
- Windows native application lifecycle and top-level window;
- one Rarog View behind a TabId-bound engine-host adapter;
- stale-safe async lifecycle with monotonic targeted request IDs, explicit invalidation, tested pending ownership and cooperative worker cancellation before presentation;
- stale-safe Rarog frame request lifecycle;
- native event-loop integration with bounded off-UI render work;
- viewport resize, DPI redraw routing and DX12 presentation with event-loop-thread native surface creation;
- deterministic local `about:blank` start document tracked as a pending browser navigation and committed into history only after successful native/Rarog initialization;
- bounded native surface recreation only for Rarog-reported surface acquisition failure;
- clear separation between the privileged shell and Web content surface;
- Windows developer executable built, headless-smoked, full native-window/Rarog/DX12-smoked and retained by CI;
- full GPU device-loss recovery is blocked on a stable Rarog recovery contract tracked in issue #6.

The existing rarog-window binary remains a small engine reference host. Product UX belongs here.

## Z2 — Navigation and Tabs

- platform-independent per-tab navigation intent and browser-history model with stable navigation/history identities;
- supersession, stop and stale-completion rejection for browser-owned navigation work;
- stable-ID multi-tab create/close/reorder product model plus two-phase TabActivationId selection lifecycle, an identity/generation-bound neutral presentation handoff guard and presentation-aware active-tab close coordination; Windows redraws are generation-gated, native tab creation owns one Rarog View per stable TabId, keyboard activation and Ctrl+W close use a confirmed hidden-window neutral fallback, closed source Views are retired only after fallback presentation, and rapid A → B → C supersession is integration-tested with B already in flight and only C allowed to become the accepted target;
- window-owned address bar edit/display model with stable TabId-bound raw submissions;
- back/forward/reload/stop are wired from the Windows shell into exact tab/navigation worker targets; Stop uses an acknowledged exact Rarog cancellation before removing product loading state, and general HTTP(S) navigation uses the pinned Rarog Fetch/View contract with Host-owned context-scoped network authority and deterministic localhost commit/presentation coverage;
- derived tab-strip chrome projects stable tab order, committed selection, pending activation target, per-tab loading and current browser display location without treating address-bar edit text as tab metadata; page-title observation remains blocked on a supported Rarog View title contract tracked in issue #18;
- keyboard-first browser commands are modeled and atomically dispatched against committed active-tab identity, including new-tab creation, presentation-aware close, pending-aware tab cycling and navigation controls; Windows maps Ctrl+T, Ctrl+W, Ctrl+Tab/Ctrl+Shift+Tab, Alt+Left/Alt+Right and Ctrl+R to browser-owned commands, with Escape requesting exact Stop while loading; Web-content input dispatch remains separate and blocked on issue #16;
- loading-state chrome is projected through a derived committed-tab snapshot with pending-navigation Reload/Stop state; native chrome rendering remains separate.

## Z4 — Security and Process Integration

Tracks Rarog process/isolation maturity rather than replacing it.

- host/site process integration starts with an `EngineHost`-owned committed-document authority snapshot derived only from the current process-local EngineHost incarnation, live Rarog Host navigation context and Site-process assignment, bound to that Host incarnation plus stable product `TabId` and current View generation; Host-incarnation allocation is monotonic/non-zero and fails closed on exhaustion, local documents expose no remote authority, pending/cancelled/failed navigation cannot displace committed authority, same-site commits reuse only Rarog-assigned process authority, cross-site commits expose replacement authority, and retired Host state fails closed rather than reconstructing or guessing a process identity; these Host/process/context tokens are ephemeral authority markers, never product identities or persisted profile/session state. This foundation does not claim production Site execution, Windows IPC, sandboxing or complete process isolation while those remain active Rarog R4 work;
- remote-content policy now installs a Zorya-owned Rarog embedder `HostPolicy`: document targets must parse through the pinned Rarog URL contract and use `http` or `https`, while malformed, relative, `file:`, `data:`, `mailto:` and custom/external schemes are blocked before any Host navigation context, Network capability or Host network operation is minted; blocked navigation cannot displace committed remote-document authority, and generic resource-request forwarding remains denied until a separately reviewed capability-routed subresource path exists. This browser policy neither duplicates Rarog Fetch semantics nor performs OS external-protocol dispatch;
- committed-document authority snapshots are replay-safe before future privileged brokering: `EngineHost::validate_committed_document_authority` resolves the current committed remote authority again through live Host state and returns `true` only for an exact EngineHost-incarnation + `TabId` + View-generation + navigation-context-token + Site-process-token match; replacement Hosts/commits, local documents, closed/recreated Views and old snapshots are stale/false even when a fresh Host reuses the same per-Host numeric counters, while missing or divergent live Host state remains fail-closed as `InconsistentNavigationState`. Revalidation itself mints no capability, network operation or IPC authority and is not yet capability brokering;
- privileged-request admission no longer exposes a generic request handle/kind/register/preflight surface. Network and Clipboard attempts are routable only through their exact specialized one-shot envelopes. Network consumption continues through canonical target policy; Clipboard consumption reaches a private Clipboard-only Host source revalidation helper only after one-shot removal and exact envelope equality, returning only stale/unsupported denial. No public source-only admission primitive, allow result, Rarog capability ID/grant, `rarog-broker` dependency, Host network operation, OS clipboard access or IPC action is introduced; a later capability/backend slice must add separately reviewed allow policy and revalidate immediately before any actual grant/operation;
- Network target admission now uses only canonical pinned Rarog security identity: `EngineHost::preflight_network_target` revalidates the exact Host-minted committed source first, including exact canonical Origin equality against current live View/Host state, then uses that already Host-cross-checked source Origin `SiteIdentity`; only after source revalidation does it parse the target through `rarog_url::WebUrl`, reject malformed/relative and non-HTTP(S) targets, and require schemeful same-site equality using Rarog `SiteIdentity`. Ports do not split a Site, while scheme/site changes are denied. Browser display/history strings and custom registrable-domain logic are not used for security identity, missing/divergent Host state remains fail-closed, and even a current same-site HTTP(S) target still yields only `DeniedUnsupported`: no allow result, broker dependency, capability grant, Host operation or Fetch-policy reimplementation is introduced;
- future privileged attempts now also have a bounded one-shot product lifecycle: `EnginePrivilegedRequestTracker` shares one configured pending-request limit across specialized Network and Clipboard requests and assigns process-global monotonic non-zero request IDs. The obsolete generic request handle, product request-kind taxonomy and generic tracker registration/preflight compatibility surface have been removed; source-only Network/Clipboard labels are no longer representable as routable request identity. Network registration instead requires an `EngineHost`-minted `EngineCommittedDocumentSource`, which binds the exact committed authority to the exact canonical Rarog `Origin` of the live committed HTTP(S) document; `EngineNetworkPrivilegedRequest` retains that exact source together with an exact raw target capped at 4 KiB, a canonical pinned-Rarog `FetchMethod`, a bounded canonical pinned-Rarog `HeaderList`, an exact optional request body, and canonical pinned-Rarog `RequestMode`, `CredentialsMode`, `RedirectMode` and `RequestDestination` values. Headers are re-bound through Rarog `iter()` + `append()` into fixed product limits of 64 entries / 16 KiB aggregate canonical bytes so caller-selected header-list capacities are erased from identity. Body compatibility is delegated to Rarog `FetchMethod::permits_body()` rather than a duplicate GET/HEAD table; absence and a present-but-empty body remain distinct, body bytes are immutable/shared across handle clones, each body is capped at 1 MiB and one tracker retains at most 16 MiB of pending body bytes by default. `RequestDestination::Other(String)` is retained exactly but capped at 256 bytes before request-ID allocation, pending-slot use or body-budget consumption. Body/header/target/destination and aggregate body-memory bounds fail before request-ID allocation or pending-slot consumption, with checked arithmetic. The source `Origin` is minted only by `EngineHost::committed_document_source` from the canonical live Rarog `View::document_url()`, rejects non-HTTP(S), opaque, missing or divergent source state, and cross-checks its Rarog Site against the live Host Site/process assignment; Zorya adds no Origin parser, default-port table or host normalization. Network registration itself still performs no target parsing, source revalidation, authorization or network execution. Consumption removes the stored identity first and centrally releases its tracker-accounted body bytes before kind/equality/policy checks, so exact consumption, same-ID source/kind/method/header/body/mode/credentials/redirect/destination/target mismatches and cross-kind burns cannot strand pending body budget. Raw targets, source-Origin/host serialization, header names/values, body contents and custom destination contents stay redacted from `Debug`; only the source authority, safe aggregate sizes/presence, canonical method, finite mode/credentials/redirect values and destination kind/byte count may be shown. Replay across the same/replacement tracker or EngineHost remains fail-closed, stale authority is still rejected before target classification, and even a current exact same-site fully envelope-bound request remains `DeniedUnsupported`; mode/credentials/redirect/destination binding and the exact response-body limit are correlation only. Compatibility paths bind the pinned Rarog 64 MiB default; the explicit path accepts only `1..=MAX_PRIVILEGED_NETWORK_RESPONSE_BODY_BYTES`, where that product maximum equals the pinned Rarog default, and invalid limits fail before request-ID, pending-slot or request-body-budget consumption. Same-ID response-limit substitution burns the stored request after request-body accounting is released, and the numeric limit may appear as safe Debug metadata. No response allocation/buffering/enforcement, Origin-header synthesis, CORS/Fetch execution or capability/Host operation is introduced. Clipboard requests are now likewise specialized and canonically source-bound before any future grant: `EngineClipboardPrivilegedRequest` binds the exact Host-minted `EngineCommittedDocumentSource` (committed authority plus canonical Rarog Origin) to `ReadText` with an exact `1..=1 MiB` result limit or to exact UTF-8 `WriteText` capped at 1 MiB. Cloned handles share immutable Origin/write storage, one tracker independently retains at most 16 MiB of pending Clipboard write text by default, and removal releases that accounting before type/equality/source checks. Exact source/Origin, operation, limit and text substitutions burn one-shot identity; Origin/host/port and write contents remain Debug-redacted. Exact consumption revalidates authority, re-mints the live canonical source and requires exact source equality. Even an exact current Clipboard request remains `DeniedUnsupported`, with no Rarog Clipboard capability grant, OS clipboard access, permission decision or internal-page privileged action introduced;
- crash recovery;
- capability brokering;
- download/file/external-protocol hardening;
- privileged internal-page identity now starts from a Zorya-owned finite `EngineInternalPage` rather than an address/history string: the bundled Start page is loaded only through a dedicated EngineHost path that selects the embedded HTML itself and mints an exact `EngineCommittedInternalPageAuthority` bound to Host incarnation, stable `TabId`, View generation, page kind and a monotonic non-zero internal-document token. Generic local HTML never mints this authority; same-page reload rotates the token; View/Host replacement and committed remote navigation invalidate stale snapshots, while pending/failed/cancelled/blocked remote attempts preserve the still-committed internal page. Revalidation cross-checks live Rarog local-document state (`about:blank` base, no remote document URL/context), so the persisted/display `about:blank` label is not authority. This is identity/provenance only: no privileged internal action, JavaScript/native bridge, permission decision, capability grant or custom externally navigable internal scheme is introduced;
- permission mediation;
- Windows hardening.
